# キックオフ: メモから初稿を作る

ユーザーのメモや資料から、新しい発表の初稿 (`slides.qmd`) を作るまでの手順。順に進め、各ステップの完了条件を満たしてから次へ進む。

## 1. メモを読み込む

メモを最後まで読み、各記述を次のどれかに仕分ける。

- **資料の内容**: 輪読資料や文献から取った説明・引用
- **ユーザーの意見・疑問**: 「〜ではないか」「〜は筋が通らない」「〜なのはなぜ?」
- **迷い**: 「これ必要か?」のように、入れるかどうか決めていない章や話題
- **脇道**: 「面白い単語」のように、本題の外にある素材
- **不確かな記述**: 推測 (「多分〜ということ」)、定義の揺れ、誤字らしき語

完了条件: メモのすべての記述をどれかに仕分けた。

## 2. 質問する

AskUserQuestion で 2 ラウンドに分けて聞く。1 ラウンドの質問は 4 問まで。選択肢にはメモの具体的な語を使う (「背景の扱い」ではなく「欠乏の専制・Bayh-Dole 法の扱い」)。推奨がある選択肢は先頭に置き、理由を description に書く。ユーザーが選択肢以外の答え (Other) を返したら、その文面を読んで、聞き方の前提が崩れていないかを確かめる。

**ラウンド 1: 前提**

| 軸 | 答えで変わるもの |
|---|---|
| 発表時間・提出物 | 枚数 (本文は 1 分 1 枚が目安)、`pdfpc-duration`、PDF 単体で読める必要があるか |
| 聞き手と発表形式 | 用語の説明の深さ。輪読なら「資料をこう理解した」が伝わる構成にする |
| 持ち帰ってほしいこと | 構成の軸 (全体像の網羅 / 一つの論点 / 自分の研究への当てはめ / 事例中心) |
| 脇道の扱い | 導入のつかみ / 背景として本編に 1 枚 / 付録 / 使わない |

**ラウンド 2: 中身**

| 軸 | 答えで変わるもの |
|---|---|
| 迷っている章 | 入れる / 短く 1 枚 / 入れない |
| ユーザーの意見・疑問 | 最後に「考察・疑問」としてまとめる / 該当箇所に注記 / 入れない |
| 文字量 | 文で書く (PDF 単体で読める) / 箇条書き / キーワード中心 + 口頭 |
| 出典 | 資料名と、表記する位置 (表紙・最終ページ / 引用したスライドごと) |

ステップ 1 で迷いや脇道に仕分けた記述がなければ、対応する軸は聞かずに飛ばし、代わりにメモ固有の論点を聞く。

完了条件: 両方の表の軸がすべて、回答済みか「任せる」と明示された状態になった。

## 3. 初稿を書く

ステップ 2 の回答に沿って `slides.qmd` を書き換える。書き方は `slides.qmd` のサンプルと README を参照。

本文には、ユーザーが確認しなければならない箇所を `<!-- TODO: ... -->` で残す (PDF には出ない)。対象は次の 3 種類。

- **不確かな記述**: ステップ 1 で仕分けたもの。どちらの記述を採ったか、何を資料で確認すべきかを書く
- **Claude の補足**: メモにない説明や論点を足した箇所。ユーザーの理解として発表されるので、すべて印を付ける
- **プレースホルダー**: 名前、発表日など

完了条件: メモの各記述を、スライドに反映するか、回答に従って意図的に外した。

## 4. ビルドして目で確かめる

`make` でビルドし、全ページを画像にして見る。

```sh
quarto typst compile slides.typ "$TMPDIR/p-{0p}.png" --ppi 80
```

はみ出し、文字化け、日付などのメタデータの表示崩れ (`Invalid Date` など) を探す。

完了条件: 全ページを見て、どのページも下端のフッターに本文が重なっていない。表示が崩れたページは直して再ビルドした。

## 5. 報告する

次の 3 点をユーザーに伝える。

- 構成 (セクションと枚数)
- ステップ 3 の TODO の一覧。Claude の補足は「消してよい」と明記する
- 下端ぎりぎりのページなど、加筆するときに注意が要る箇所
